# Threat model

## What is protected

- The ability to run commands on the computer through the agents' PTYs. Any authentication bypass equals remote code execution.
- Agent output (it can contain code, paths, secrets).
- Passkeys and web sessions (the key to the first two).
- The owner's files and secrets that agents can reach.

## From whom, and by which layer

The layers are independent: getting past one must not give access.

| Threat                                               | Layers of defense                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scanners and bots from the internet                  | The server listens on `127.0.0.1` only. Outside access goes only through `tailscale serve` inside the tailnet, to a separate port that answers only while remote access is on. `tailscale funnel` is forbidden.                                                                                                                                                                                                                             |
| Another compromised device in the tailnet            | Remote access is off by default and can only be turned on at the computer. Passkey with mandatory biometrics/PIN, rate limiting and a global login lockout, view mode by default, step-up for input, a fresh passkey check for dangerous actions. Tailscale ACLs (recommended in the README).                                                                                                                                               |
| Malicious web page: CSRF                             | `SameSite=Strict` cookie, `Origin` check on every request with side effects, mandatory `Content-Type: application/json`, `Sec-Fetch-Site` check.                                                                                                                                                                                                                                                                                            |
| Cross-site WebSocket hijacking                       | `Origin` and `Host` checks on every upgrade, `SameSite=Strict` cookie.                                                                                                                                                                                                                                                                                                                                                                      |
| DNS rebinding                                        | `Host` header allowlist, rpID and origin come from the config only.                                                                                                                                                                                                                                                                                                                                                                         |
| XSS                                                  | Strict CSP (`script-src 'self'`, no inline or eval, styles only `'self'` + nonce), terminal output only in xterm.js, React escapes text, no `dangerouslySetInnerHTML`.                                                                                                                                                                                                                                                                      |
| Clickjacking                                         | `frame-ancestors 'none'`, `X-Frame-Options: DENY`.                                                                                                                                                                                                                                                                                                                                                                                          |
| Stolen unlocked phone, forgotten tab                 | 30 minutes idle, 12 hours absolute, input needs step-up (5 minutes), dangerous actions need a passkey right before the action, the kill switch at the computer (`npm run killswitch`) revokes all sessions.                                                                                                                                                                                                                                 |
| WebAuthn guessing and replay                         | Single-use challenge on the server (2 minutes), challenge bound to its purpose and session, signature counter check, `userVerification: required`.                                                                                                                                                                                                                                                                                          |
| Someone else's phone joining                         | The join code is issued only at the computer, single use, 10 minutes, burned before registration, failed attempts count toward the lockout. Issuing a code and joining a device are written to the audit log and sent to ntfy. Recovery is local only (`npm run reset-auth`).                                                                                                                                                               |
| Prompt injection in agents                           | Agents start only from `agents.json`, with a cleaned environment (variable allowlist), in allowed working folders (traversal and symlink checks), auto-approve flags are forbidden. Agents run with the owner's rights, so prompt injection is more dangerous than under a separate account. No "always allow": every approval is shown in full and needs control mode.                                                                     |
| A chat agent acts without the owner knowing          | Claude Code starts in `default` mode and hands every permission request to the server, Codex with the `untrusted` policy and user review. Answers are one-time only, "always allow" is never sent, unknown requests are refused. Answering needs control mode and is written to the audit log.                                                                                                                                              |
| Reading arbitrary files through image previews       | The browser asks for an image by a random id issued for a file the agent touched, never by path. The file is checked when served: real path inside `allowedRoots` (outside them only if the tool call that read the file has already succeeded), image extension and signature, no SVG; the response carries a `sandbox` CSP and `nosniff`.                                                                                                 |
| An agent on "Allow all" does something harmful       | Only the owner turns it on: from the phone with a new passkey check, with an ntfy notification and an audit entry. The agent stays in its asking mode and the server answers "allow once" for the owner, so every action shows in the chat and the audit log. The kill switch turns it off for all agents. Residual risk: in this mode prompt injection in files or in another agent's answer can lead to actions the owner did not review. |
| Shutting the computer down from someone else's phone | Only as a dangerous action: a new passkey check bound to this action. The command is fixed, with no data from the request. One minute to cancel, an ntfy notification, an audit entry. Residual risk: whoever has your phone and passkey can shut the computer down, that is, interrupt work (without access to data).                                                                                                                      |
| One agent controls another                           | Only the owner links agents, in control mode, with a limit of up to 20 messages, and it is written to the audit log. Every action of either agent still needs approval. Claude commands that change settings without a card (`/config`, `/auto-mode-setup`) are refused.                                                                                                                                                                    |
| Secrets leaking through logs and notifications       | Pattern-based masking before writing to the audit log and sending to ntfy, agent output never goes into notifications, input text is not logged by default.                                                                                                                                                                                                                                                                                 |
| WebSocket abuse                                      | Message size limit, rate limit, ping/pong with a timeout, session and mode checks on every message, periodic closing of connections whose session expired.                                                                                                                                                                                                                                                                                  |
| Local access to the database                         | The database file sits in a folder only the current user can access, session ids are stored as SHA-256.                                                                                                                                                                                                                                                                                                                                     |

## Out of scope

- An administrator or malware on the computer itself with the owner's rights: they can do everything without this app.
- A compromised Tailscale account together with a compromised passkey.
- Vulnerabilities in the agents themselves (Codex, Claude Code, etc.), beyond limiting their environment and working folders.
